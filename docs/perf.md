# Performance Benchmarks (T12)

This document records measured release-build performance on the deterministic 1 GiB (`1,073,741,824`-byte) synthetic JSONL corpus generated by `scripts/gen-fixtures/gen_bench_corpus.py` and executed by `scripts/bench.sh` (`PLAN.md` §7, §8, §9, §10 T12).

## 1. Benchmark Methodology & Corpus

- **Harness**: `./scripts/bench.sh --offline` (plus Criterion micro/pipeline benchmarks in `crates/kakeibo/benches/pipeline_bench.rs`).
- **Corpus**: `1,073,741,824` bytes (`1.00 GiB`) across `64` synthetic session files (`33` Claude Code JSONL files + `31` Codex CLI rollout JSONL files, `30,688` total deduplicated turns, `seed = 42`), generated in an isolated temporary `HOME` directory.
- **Measurement**: Wall-clock elapsed time (`time.perf_counter()`) and kernel peak resident set size (`/usr/bin/time -l` `maximum resident set size` on macOS Darwin arm64) for `kakeibo sessions` (full discovery → index/parse → attribution → flag evaluation → pricing → table report).
- **Parity check**: `diff -u` verifies byte-identical CLI output between `--no-cache` and SQLite-cached runs both before and after appending a new turn to an active session file.

## 2. Measured 1 GiB Results (Release Build, macOS arm64)

| Pass | Command | Wall-Clock Time | Peak RSS | §7 Target | Status |
|---|---|---:|---:|---|---|
| Cold (uncached, `rayon` + `memchr`) | `kakeibo --no-cache sessions` | `1.641 s` (`1,641.45 ms`) | `93.86 MB` (`89.52 MiB`) | Cold ≤ `10.0 s`, Peak RSS ≤ `300 MB` | Pass |
| Cold (initial SQLite index build) | `kakeibo sessions` (empty cache) | `1.042 s` (`1,042.20 ms`) | `169.92 MB` (`162.05 MiB`) | Cold ≤ `10.0 s`, Peak RSS ≤ `300 MB` | Pass |
| Warm cached (run 1) | `kakeibo sessions` | `534.33 ms` (`0.534 s`) | `116.80 MB` (`111.39 MiB`) | Warm ≤ `300 ms` (CI runner target for T16), Peak RSS ≤ `300 MB` | Tracked for T16 |
| Warm cached (run 2, best) | `kakeibo sessions` | `526.24 ms` (`0.526 s`) | `112.36 MB` (`107.16 MiB`) | Warm ≤ `300 ms` (CI runner target for T16), Peak RSS ≤ `300 MB` | Tracked for T16 |
| Incremental append (`+1` turn, ~640 B) | `kakeibo sessions` (after 1-line append) | `684.35 ms` (`0.684 s`) | `124.11 MB` (`118.36 MiB`) | Resumes from `last_newline_offset`, Peak RSS ≤ `300 MB` | Pass |
| Post-append uncached verification | `kakeibo --no-cache sessions` | `1.016 s` (`1,016.26 ms`) | `97.85 MB` (`93.31 MiB`) | Byte-identical output to incremental cached run | Pass |

- **SQLite index size (`index.sqlite`)**: `50,966,528` bytes (`48.61 MiB`) for `30,688` turns (`~1.66 KiB/turn` of derived text-free `TurnRecord` ledger rows + checkpoint metadata; zero raw prompt or tool text stored).
- **Warm cache analysis (for T16)**: Deserialising `30,688` `TurnRecord` rows from SQLite and running full per-turn attribution (`attribute_session`) + v1 flag evaluation (`evaluate_flags_v1_default`) across all 64 sessions takes `~526 ms` on 30,688 turns. Caching derived session-level summaries alongside turn records in T16 (`Perf pass & Bento interop`) will eliminate re-running attribution/flag math on unchanged sessions during summary views (`kakeibo sessions`, `flags`, `top`).

## 3. Reproducing Locally

```sh
# Full 1 GiB release benchmark (creates and cleans up a temp directory under /tmp):
./scripts/bench.sh

# Fast smoke check on a 16 MiB synthetic corpus:
./scripts/bench.sh --bytes 16777216 --files 8

# Criterion micro- and pipeline-level benchmarks:
cargo bench --bench pipeline_bench
```
